# 本组读题与本地缓存

- 每组题抽取完成后才创建一个后台预加载线程；只准备这组题的题干，当前/下一题优先。普通题数和闯关题数由现有出题规则决定，不修改过关门槛、奖励或观看记录。
- 每题显示后自动读一次，保留「听一听」；鼠标进入题干区域重听。区域内部移动不重启；离开再进入有1.2秒冷却，正在准备/朗读同一题时不叠加。
- 后台只合成文件，不操作Tk或播放。Tk每60毫秒查看当前题结果。答题、换题、结束和关闭会停止播放器并使旧结果失效；组结束取消队列中尚未发送的请求。已发送的HTTP请求最多等待原有20秒超时，可以完成并保存缓存，但不会播放旧题。
- 音频目录：安装目录 `data/tts_cache`。新缓存键v2包含题干、provider、endpoint、speaker、resource、编码、采样率、语速和音量，不包含API key。临时文件写完、flush/fsync后再原子替换。同key任务复用Future并有线程安全缓存锁。
- 新键不会冒险复用参数不完整的旧缓存键；旧MP3保留但升级后的首轮可能重新合成。之后同文本、同音频配置可离线命中新缓存。
- 热缓存通常很快开始本地播放；首题冷缓存仍有网络耗时，显示“语音准备中… 可继续答题”。合成/播放失败不阻止答题，无反复错误弹窗。默认只读题干，不包含答案或解析。
- Windows采用非阻塞、可停止的MCI播放器；实际声卡输出及完整GUI交互仍需在目标电脑验证。没有批量生成题库或新增外部存储。

## 测试

`python -m unittest discover -s tests -v`；需要已安装requirements中的pypinyin。
`test_quiz_voice.py`全mock，不联网/播放/计费。可选`test_quiz_voice_ui.py`需要Tk和显示环境；Linux可以`xvfb-run -a python -m unittest discover -s tests -p test_quiz_voice_ui.py -v`。

此功能分支只包含朗读改动。现有Windows副本里未推送的大闯关、config.local合并、加时和题库内容不作为本分支的附带提交；向该副本部署时需仅移植朗读改动，不能覆盖成GitHub旧版文件。
